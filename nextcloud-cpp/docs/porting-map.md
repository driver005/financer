# What is ported

Paths are relative to the Nextcloud tree in `docs/nextcloud-server`. **Ported** means the behaviour exists
here and is tested; **Reduced** means a deliberate subset (stated); **Replaced** means done differently;
**Not ported** means it does not exist here.

## Kernel

| Nextcloud | Status | Here |
| --- | --- | --- |
| `lib/private/Server.php`, `lib/public/IContainer.php`, `IServerContainer` | Replaced | `ServiceRegistry`: named services with string arguments instead of a typed DI container |
| `lib/private/EventDispatcher`, `lib/public/EventDispatcher` | Reduced | `EventBus`: synchronous, string topics with a `*` suffix pattern, string payloads, failing handlers isolated |
| `lib/private/Route`, `lib/public/Route`, every `appinfo/routes.php` | Reduced | `Router`: method + pattern, `{name}`, `{*rest}`, 404/405/OPTIONS/HEAD. No route requirements (regex), no URL generation |
| `lib/private/App/AppManager.php`, `appinfo/info.xml` | Replaced | `Kernel` + the plugin table in the ABI: name, version, description, requirements, ordering, skip on failure. Enabling is the `plugins` setting. No app store, no per-user app enablement, no `info.xml` |
| `lib/private/Config.php`, `config/config.sample.php`, `AppConfig` | Reduced | `Config`: one text file with `[plugin]` sections, read-only at run time; what changes while the server runs lives in the `settings` plugin (see below) |
| `lib/private/Log`, `lib/public/ILogger.php` | Reduced | `Logger`: levels, stderr sink, per-plugin source |
| `occ`, `core/Command` | Reduced | `CommandRegistry` + `nextcloud occ`: `list`, `status`, `plugin:list`, `config:get`, `background:run|list`, plus what plugins add. No interactive prompts: secrets come from `OC_PASS` |
| `lib/private/BackgroundJob`, `cron.php` | Reduced | `JobScheduler`: interval jobs added by plugins (`host.add_job`), run once a second while serving and by `occ background:run`. No job queue with arguments, no persistence of the last run |
| `lib/private/Authentication` (login chain) | Reduced | the request pipeline: app password (`auth.token`), then password (`auth.authenticate`), then second factor (`auth.second_factor`, `X-NC-OTP`). Basic auth and Bearer tokens (`auth.bearer*`, used by `oauth2`); `/public.php/` is left to the plugin that serves it (share token as user name). No sessions, cookies or CSRF tokens. **SAML 2.0** (`saml` plugin, counterpart of `user_saml`, one identity provider): SP-initiated Web SSO, `GET /index.php/apps/user_saml/saml/login` (HTTP-Redirect with a deflated AuthnRequest), `POST .../saml/acs` (HTTP-POST), `GET .../saml/metadata`. The response is checked with `libxml2` (no DTD, exclusive canonicalization of the signed element and of SignedInfo) and BoringSSL: the assertion must be covered by an enveloped RSA-SHA256/512 signature that verifies with the one configured certificate (`idp_certificate_file`, never a key from the message), with a single reference to the signed element whose ID occurs once, plus issuer, audience, recipient, `InResponseTo`, validity window, one use per request and per assertion. The tests sign with `xmlsec1` (an independent implementation) and try signature-wrapping variants, a weaker signature, wrong audience/recipient/issuer/time and DTD documents. A person is created as an account and gets an app password (shown once). Not done: encrypted assertions, ECDSA signatures, single logout, IdP-initiated login, signed AuthnRequests, several providers, role/group mapping |
| `lib/private/DB`, `lib/public/IDBConnection.php`, `lib/private/Migration` | Reduced | the `db` plugin: SQLite, `db.exec|query|migrate`, migrations applied once per plugin and version in a transaction. No Doctrine/query builder, no other database engine |
| `status.php` | Ported | `GET /status.php` (adds the plugin list) |
| `ocs/`, `lib/private/OCS` | Reduced | `nc::http::ocs()` builds the OCS v2 JSON envelope; no XML format, no `format=` negotiation |
| `remote.php`, `public.php`, `index.php` | Replaced | one router; the URLs `/remote.php/dav/...` and `/s/<token>` are kept so clients work |
| HTTP server (Apache/nginx + PHP-FPM) | Replaced | `HttpServer`: HTTP/1.1, one thread per connection, `Content-Length` and chunked bodies, `Expect: 100-continue`, **TLS 1.2+ with BoringSSL** (`tls_cert`, `tls_key`), no keep-alive, no HTTP/2, no certificate reload without a restart |
| `lib/private/AppFramework` (controllers, middleware, DI of controllers) | Reduced | `sdk/plugin/include/nextcloud/app.h`: `nc::app::App` registers routes with `RouteOptions` (access PUBLIC/USER/ADMIN, plain or OCS error format) instead of annotations; `Middleware` with `before_controller`, `after_controller`, `after_exception`; ready-made session, admin and error middleware (`use_defaults()`); handlers throw `HttpError`. Used by every plugin that has signed-in or administrator-only routes (`settings`, `theming`, `updatenotification`, `webhook_listeners`, `workflowengine`, `user_status`, `weather_status`, `notifications`, `activity`, `comments`, `systemtags`, `tokens`, `twofactor`, `trashbin`, `versions`, `lookup`, `users`, `groups`, `mail`, `oauth2`, `previews`, `federation`, `calendar`, `cloud`). Routes that stay on `add_route` are the ones that decide for themselves: anonymous protocol routes (OCM, public links, the token endpoint's client authentication), WebDAV and CalDAV/CardDAV handlers (they answer 401/403/207 in DAV terms) and discovery redirects. No dependency injection, no request-body binding to typed parameters, no CSRF token (the API is Basic/Bearer authenticated, not cookie based).  |
| `lib/private/Security`, CSP, rate limiting, brute force protection | Reduced | CSP and `nosniff` on downloads, constant time comparisons, uniform answers for bad tokens and unknown users, request smuggling shapes refused. No rate limiting or lockout |
| `lib/private/Template`, themes, JS front end (`core/`, `apps/*/src`) | Not ported | the runner serves APIs only |

## Plugins

| Nextcloud | Status | Plugin |
| --- | --- | --- |
| `lib/private/User`, `apps/provisioning_api` | Reduced | `users`: accounts, PBKDF2 passwords, first account is admin, basic auth, create/read/edit/delete/list, and the services `users.get|email|by_email|search|is_admin|list_admins` that other plugins use. Directory sign-in is the `ldap` plugin; there are no other user backends |
| `apps/user_ldap` | Reduced | `ldap`: sign in with a directory: bind (service account or anonymous), find exactly one entry of an object class by a user attribute (filter built as a structure, so names cannot inject terms), bind as that entry with the password; the person gets an account (`users.ensure`) with display name and mail from the directory. Plain TCP only (no LDAPS/StartTLS), no group sync, no paging, no user listing from the directory, no avatars. Any plugin can now offer `auth.authenticate*` and the kernel tries them in turn |
| `lib/private/Group` | Reduced | `groups`: groups, membership, OCS group API, `groups.*` services (used by group shares). No subadmins, no group backends |
| `lib/private/Authentication/Token` | Reduced | `tokens`: app passwords (create, list, revoke), stored as digests |
| `apps/twofactor_totp`-style, `apps/twofactor_backupcodes` | Reduced | `twofactor`: TOTP (RFC 6238) with replay protection, 10 backup codes. No U2F/WebAuthn, no per-session state |
| `lib/private/Files`, `apps/files` | Reduced | `cloud`: per-user storage, quota, ETags. No cache/index database, no file ids. External storage, encryption at rest and previews are separate rows below |
| `apps/dav` (files) | Reduced | `cloud`: GET, PUT, MKCOL, DELETE, MOVE, COPY, PROPFIND (fixed property set), `X-OC-Mtime`. Single byte ranges and `If-None-Match` on downloads; the chunked-upload API (`/remote.php/dav/uploads`, chunks joined by number, `OC-Total-Length`). No PROPPATCH on files, no REPORT/SEARCH, no locking, no bulk upload, no multi-range |
| `lib/private/Share20`, `apps/files_sharing` | Reduced | `cloud`: shares are rows of the `db` plugin (`nc_shares`; the text file of earlier versions is imported once and renamed `shares.db.imported`); shares with a user, with a group and by public link, permissions (read/update/create/delete), expiry, OCS create/list/get/delete, `/s/<token>`; **a received share appears in the recipient's top folder** (numbered when the name is taken) and is served from the owner's tree with the share's permissions, its changes recorded for the owner (activity, trash, versions); shares follow moved/deleted files and deleted accounts. Links can have a password (PBKDF2, header `X-NC-Share-Password`) and can be upload-only ("file drop", numbered names, no overwrite) or read+upload. What a recipient writes counts against the owner's quota, and a mounted folder shows its size in the top-level listing. Shares by mail (type 4) are a link mailed to one address (`mail.send`), working like a link share. **Resharing**: someone who received an item with the "share" right (16) can share it (or a part of it) on to people, groups and links, never with more rights than they have and never to another server; the new share belongs to the owner and records the initiator (`uid_initiator`), both can remove it, and it ends when the share it hangs from ends or expires (removal at once on delete, within a minute on expiry). |
| `apps/files_trashbin` | Ported (core) | `trashbin`: deleted files and folders move to a trash with the original path, listed, restored (next to the original if the place is taken), removed, expired by a job. No trash of shared items |
| `apps/files_versions` | Ported (core) | `versions`: old content kept on overwrite, newest `max_versions` per file, restore, history follows a move, expiry job. No per-version labels, no versions of shared items |
| `apps/dav` (CalDAV) | Reduced | `calendar`: calendars, events/tasks, PROPFIND, REPORT (multiget, query with time range, sync-collection), MKCALENDAR, PROPPATCH of the display name, discovery. **Sharing**: the owner POSTs `<cs:share>` (read or read-write) and the shared calendar appears in the other person's home as `<name>_shared_by_<owner>` (read-only ones refuse changes; the sharee can leave). **Scheduling (iTIP)**: an event whose ORGANIZER is the saving account puts `METHOD:REQUEST` in each attendee's `inbox` (and `CANCEL` for dropped or deleted ones); an attendee who changes their PARTSTAT or deletes the event sends a `REPLY` to the organizer's inbox and the organizer's copy shows the answer; addresses without an account get a plain mail. The principal names `schedule-inbox-URL` and `calendar-user-address-set`. No auto-accept, no free/busy, no RSVP mail with an attached .ics, no `SCHEDULE-AGENT` handling, no subscriptions, no free/busy, no expansion of recurring events (they match every time range), no deletion tracking in sync |
| `apps/dav` (CardDAV) | Reduced | `contacts`: address books, vCards, PROPFIND, REPORT, discovery. Address books are shared like calendars (`POST <cs:share>`). **System address book**: a read-only book "Accounts" (`system_shared_by_nc-system`) with a vCard for every enabled account and for the people on other servers this server has exchanged shares with (`CLOUD` field), refreshed when accounts change and every five minutes. |
| `lib/private/Mail/Mailer`, `Message`, `Emailer` | Reduced | `mail`: plain/HTML/alternative messages, UTF-8 headers, spool, sendmail, SMTP (no TLS, no AUTH). No attachments, no email templates |
| `lib/public/Activity`, the `activity` app | Reduced | `activity`: stream of file, share and account events per user, API, retention job |
| `lib/public/Notification`, `apps/notifications` | Reduced | `notifications`: push by service, event or command; list/get/dismiss API; retention job. No push to devices |
| `apps/encryption` | Reduced | `cloud`: with `[cloud] encryption_key` (64 hex digits) or `encryption_key_file`, every file is stored as ChaCha20-Poly1305 with its own key (derived from the server key, the account and a random salt) and the account bound in as associated data; tampering and files moved between accounts are detected; plain files from before are still read, `occ encryption:encrypt-all <user>` converts them; sizes, ETags, shares, links and the trash and versions copies keep working. **Key rotation**: `occ encryption:rotate-key <user> <old-key-file>` re-encrypts the files, the trash and the versions from the old key to the one in the config (repeatable; stops at the first file that does not verify). One server key only: no per-user keys derived from passwords, no recovery key, calendars and contacts (in the database) are not encrypted |
| `lib/private/Preview` | Reduced | `previews`: `GET /index.php/core/preview.png?file=&x=&y=` for PNG, JPEG, GIF, BMP, PNM (Netpbm), WebP (libwebp), TIFF (libtiff, first page, read from memory) and SVG (lunasvg, drawn at its own size up to 2048 px, no scripts, no external files) pictures (formats recognised by their first bytes, size read before decoding, 20 MiB / 8192 px / 40 MP limits), scaled to fit and returned as PNG, cached by file version; access follows shares (`cloud.can_access`). No video, PDF, office or HEIC previews (`libheif` is in the registry, but there is no way here to make HEIC test files), no cropping modes, no mimetype icons |
| `apps/oauth2` | Reduced | `oauth2`: authorization server, authorization code flow with PKCE (S256), client secrets, one-time codes, rotating refresh tokens, Bearer tokens accepted by the kernel (`auth.bearer*`), clients registered with `occ oauth2:add`. Consent is implied by arriving signed in (no login or consent page), no scopes, no client credentials/implicit/password grants |
| `apps/files_external` (local backend) | Reduced | `cloud`: folders of the host an administrator lists in `[cloud] external_mounts = Name=/path:ro|rw[:group]; ...` appear in every (or the group's) top folder, read-only or read-write. **WebDAV backend**: `[cloud] external_webdav = Name=URL|user|password-file[|rw][|group]` mounts a folder of another WebDAV server (read, range, write, copy, move, delete, folders; links rewritten into the mount; downloads forced to attachment). **S3 backend**: `[cloud] external_s3 = Name=URL|bucket|ACCESSKEY|secret-file[|rw][|prefix=dir/][|region=r][|group]` (AWS Signature V4, path-style addressing, so MinIO and Ceph work; listing with continuation, ranges, put, copy, move and delete of files and of "folders" (key prefixes), folder markers for empty folders; the signing code is checked against the examples of the AWS documentation). **FTP backend**: `[cloud] external_ftp = Name=ftp://host[:port][/folder]|user|password-file[|rw][|group]` (passive mode, MLSD with a fallback to LIST, ranges, put, folders, rename, recursive delete; data connections go only to the address of the control connection, local addresses need `external_ftp_allow_local`). Plain **SFTP backend**: `sftp://host[:port][/folder]|user|password-file|hostkey=SHA256:...` (libssh2 with the mbedTLS backend; the pinned host key fingerprint is required and a server with another key is refused; password sign-in only, because libssh2's mbedTLS backend does not read private keys reliably). **FTPS**: `ftps://` is explicit TLS (RFC 4217: `AUTH TLS`, `PBSZ 0`, `PROT P`, data links resume the control session); the certificate and host name are checked (`external_ftp_ca_file`), so a server that cannot prove itself gets no password. Plain `ftp://` sends the password and files unencrypted, so use it on trusted networks only; no implicit FTPS (port 990). No SMB backend, one shared account per storage (no per-user credentials, no OAuth), no trash or versions on them |
| `lib/public/SystemTag`, `apps/systemtags` | Reduced | `systemtags`: tags shared by everybody, put on a user's own files (by owner and path, no file ids), find by tag or by file, follow renames and deletes. No restricted/invisible tags, no tags on shared items |
| `lib/public/Comments`, `apps/comments` | Reduced | `comments`: comments on a file by its owner and by people it is shared with (access decided by `cloud.can_access`), delete by author or owner, the owner is notified. No threads, mentions, read markers |
| `lib/public/Capabilities` | Ported | `GET /ocs/v2.php/cloud/capabilities` merges every service named `capabilities.<name>` (cloud, trashbin, versions, calendar, twofactor, systemtags, comments, theming, updatenotification) |
| `apps/federation`, `federatedfilesharing`, `cloud_federation_api` | Reduced | `federation`: Open Cloud Mesh sharing between two servers. Discovery (`/ocm-provider/`, `/.well-known/ocm`), `POST /ocm/shares`, `POST /ocm/notifications` (accepted, declined, unshared; every notification needs the share's secret), share type 6 in the OCS share API (`name@server`), the recipient's pending/accept/decline/leave API (`remote_shares`), the owner's files read through `/public.php/webdav` with the share token as user name. An accepted share is a mount in the recipient's tree: reading (with `Range`) and, when the owner allowed it, writing, creating folders and deleting; the owner's server checks the permissions again. Downloads of 1 MiB and more are streamed: the owner's server's answer is passed on piece by piece through the plugin interface (a response can carry a body stream), so a big file never sits in memory whole; other answers (listings, small files, chunked answers) are held in memory (`[federation] max_remote_file_mb`, default 64). Outgoing requests check the certificate and the host name, never follow redirects and refuse local addresses unless `allow_local` is set. Requests between servers are signed (Ed25519 over request target, host, date and body digest; the key is in the discovery document and cached ten minutes), unsigned ones are refused with `require_signatures = true`, and `trusted_servers` limits whom this server talks to or listens to. **Group shares**: share type 9 (`group@server`) offers the share to every member of that group on the other server; one member declining leaves it to the others. The people of other servers go into the system address book (see CardDAV). Not ported: pulling address books from other servers, re-shares across servers; **Signatures**: by default Ed25519 (this project's variant of the HTTP-signatures draft); with `[federation] signature_algorithm = rsa-sha256` a server signs the way Nextcloud does (RSA-2048, PKCS#1 v1.5 over SHA-256, `Signature` header with `headers="content-length date digest host"`, key published as `publicKey: {keyId, publicKeyPem}`), and requests signed either way are accepted; an RSA-signed request made with the system's `openssl` is part of the tests. Not checked against a real Nextcloud server, and not the RFC 9421 or JWKS variants Nextcloud also offers |
| `apps/user_status` | Reduced | `user_status`: status (online, away, dnd, invisible, offline), a message with an icon and an end time, `statuses` for others (invisible reads as offline, its message hidden). No predefined statuses, no "busy from calendar" |
| `apps/webhook_listeners` | Reduced | `webhook_listeners`: administrators register `event` (exact or `prefix*`) and `uri`; events are queued and posted by a job as JSON, signed with HMAC-SHA256 (`X-Nextcloud-Signature`), five attempts with growing pauses. Same outgoing client as federation (certificates, no local addresses unless allowed). No event filters on payload fields, no user-bound tokens |
| `apps/workflowengine` | Reduced | `workflowengine`: administrators define flows (event pattern, `path` and `user` globs) with the actions `notify` and `tag`. Reacts after the fact; there is no "block access" action and no operators other than glob |
| `lib/public/IAppConfig`, `IConfig` user values, config part of `apps/provisioning_api` | Reduced | `settings`: values per app (administrators) and per person, services `settings.get_app|get_user|set_app`, OCS under `provisioning_api/api/v1/config`. No typed values, no lazy/sensitive flags |
| `apps/theming` | Reduced | `theming`: name, slogan, url, primary colour, imprint/privacy links (checked), in the capabilities and as a CSS file with variables (default, light, dark; a dark colour is lifted on the dark theme). No logos, backgrounds or per-user themes |
| `apps/updatenotification` | Reduced | `updatenotification`: daily and on `update:check`, asks `[updatenotification] url` for `{"version","url"}` and tells each administrator once per version. It never installs anything |
| `apps/weather_status` | Reduced | `weather_status`: a location per person and the next hours from a weather service (default Open-Meteo, `[weather_status] url`), cached one hour per place |
| `lookup_server_connector` and the lookup server | Reduced | `lookup`: people publish themselves (`POST .../lookup/publish`, with or without their e-mail address); `GET /index.php/lookup/users?search=` finds them by the start of name, cloud id or e-mail (3+ characters, 10 results); `lookup.search` asks the directory in `[lookup] server`, and the `sharees` suggestions include what it finds. One directory per server, no replication between lookup servers, no signed registration of remote servers |
| other `files_external` backends, `viewer`, ... | Not ported | |

## Verified

* `bazelisk test //...` (28 targets) passes with clang 18 (C++23), plain and under `--config=asan`,
  `--config=ubsan` and `--config=tsan`.
* It also passes with clang 22 (C++26, `--define=std=26`) and with congelado's `-Werror` profile
  (`--config=warnings`).
* `tools/smoke.sh` starts the real binary with all plugins and goes through upload, share link, trash and
  restore, a calendar event, the activity stream and the mail spool with curl.
* `.github/workflows/nextcloud-cpp.yml` runs the plain, asan, ubsan and tsan builds and a clang 22 / C++26
  job; its results are on the pull request.

Not done: C++26 *modules* (`import std;`). congelado's module build needs a libstdc++ 16 `bits/std.cc` and its
patched `rules_cc`; neither is available on the machines used for this port. Everything else of its Bazel
setup is in use.
